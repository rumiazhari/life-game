# Life File RPG — Phases 6–12 release notes

**Release track:** RPG integration on `rumiazhari/life-game`. **Date:** 2026-11-17 (JST). **Status:** Browser-tested release candidate, **not deployed**. Public publication/deployment was not requested or executed.

## Gameplay delivered

- **Phase 6 — Contextual events.** Deterministic employer, household and civic episodes using actual persistent companies, relatives and places. Three routes per encounter, with one guaranteed outcome. [Merged PR #25](https://github.com/rumiazhari/life-game/pull/25).
- **Phase 7 — Relationships.** NPC reciprocity, rivalry, reconciliation and betrayal grounded in existing trust/bond/memory data, with later-year callbacks. [Merged PR #26](https://github.com/rumiazhari/life-game/pull/26).
- **Phase 8 — Character progression.** Actual skills, RPG grade/perks, authored evidence and a real active employment contract modify exact 3d6 probabilities. Evidence displays a compact domain bonus. [Merged PR #27](https://github.com/rumiazhari/life-game/pull/27).
- **Phase 9 — Interlocking chapters.** Two cross-domain multi-year families: employer/civic and household/underworld; outcomes reference actual prior archived decisions and existing NPCs, not fabricated jobs or balances. [Merged PR #28](https://github.com/rumiazhari/life-game/pull/28).
- **Phase 10 — Visual interface.** Graphical choice implications, exact 3d6 success meters, fail-forward, guaranteed escape, real NPC relationship bars and 3-die roll feedback. Mobile-responsive and reduced-motion aware. [Merged PR #29](https://github.com/rumiazhari/life-game/pull/29).
- **Phase 11 — Quantitative QA.** `npm run report:rpg` produces [reproducible HTML](../../reports/rpg-integrity.html) and [JSON](../../reports/rpg-integrity.json). Initial 40/40 engine scenarios passed with 0 economy/merit violations; exact odds vs 1,200 sampled rolls/difficulty. No evidence-based balancing changes were warranted. [Merged PR #30](https://github.com/rumiazhari/life-game/pull/30).
- **Phase 12 — Release recovery.** Optional **EXPORT SAVE / IMPORT SAVE** controls in Stories: local JSON snapshot of the current `World`, subject, lineage, Hold and pending followups; corruption and schema checks; detached migration before atomic restoration. A saved active chapter continues with its original seed, NPCs, story scenes, annual-energy records, and once-only merit/ending. The two cross-life Archive and Achievements registries remain separate.

## How to use manual local backup

1. Open **YOUR STORIES** with an active Life File, then click **EXPORT SAVE**. The browser offers an unencrypted `life-file-<year>.json` download.
2. To resume the life later, open the game and select **IMPORT SAVE** from Stories, then select that JSON file. Import is opt-in; neither a file upload to a server nor automatic cloud synchronization occurs.
3. If a story is active at the time of export, the Stories panel shows a **CONTINUE** control on import. Once a chapter has already been filed, duplicate filing does not award extra merit.

**Important:** Files are plain, unencrypted JSON backups. Keep them privately. There is **no automatic active-life autosave**, and exported backups do not overwrite the existing local browser archive/achievement system. An invalid or corrupted backup is rejected without replacing the active life.

## Known limitations / deployment boundary

- Headless Chrome emulation at 320/390/768/1440 px validates responsive browser behavior; this is **not** hands-on physical **Android** device testing. Touch-specific device compatibility and long-session power consumption should be validated on actual devices separately.
- The synthetic time/heap benchmark is not a mobile performance measurement. The synthetic story prerequisite history in Phase 11 is not a naturally recorded gameplay path.
- User experience, subjective fun, and story clarity have not been verified with voluntary human participants; no such participants were fabricated.
- This work does **not** redesign or modify Lithuania 2.5D map development. Protected map files must remain untouched.
- This is **not deployed** or published; deploying to a public site is a separate action requiring the user's authorization.
