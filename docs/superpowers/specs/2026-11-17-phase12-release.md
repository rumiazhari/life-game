# Phase 12 — Release candidate: local active-game recovery, E2E and performance

**Base:** current verified master `69b05350874449034a4941e40aa4fb37a2c93764`. **Branch:** `feat/rpg-phase12-release-readiness-20261117`. Authoritative request: Issue #24 Phase 12.

## Source inspection and actual gap
`js/state.js` (protected) stores only **completed life archives**, achievements, and sound preferences using browser localStorage. It does not expose active-life save/reopen. `main.js:newFile` resets World/Lineage/Hold/S, while `js/ui.js:fastForward` advances up to 15 years; StorySystem stores active episodes, archived runs, 3d6 history and merit **inside World**. Existing RPG tests establish VM-level JSON replay, but no player-accessible mechanism restores the current active file. Implement an **opt-in, fully local JSON export/import** as an additive RPG release feature, without autosave, network calls, or a new gameplay authority. Leave permanent archive/achievement storage untouched.

## Design
- Pure `js/systems/life-file-save.js` exposes `LifeFileSave.encode({world,subject,lineage,hold,followups})`, `LifeFileSave.decode(json)` and `LifeFileSave.prepare(json)`. Export includes canonical World/S/Lineage/Hold and pending `followups` only; no object is mutated by encoding/decoding. The save schema includes a version, bounded content length (20 MB) and a deterministic non-cryptographic FNV-1a integrity checksum for accidental corruption detection (**not** an adversarial signature or encryption). Reject malformed JSON, unsupported schema, oversized files, mismatched checksums, invalid IDs/year, dangerous structural types and impossible person/world consistency **before** any global state change. Decode cannot fetch resources or execute code.
- `prepare` clones its parsed data and runs the existing `WorldSimulation.migrate`, `NpcSystem.migrate`, `StorySystem.migrate` and `RPG.migrate` idempotently on a detached copy. It never replaces a world directly. On migration error it returns a failure, not a half-restored life. Preserve ongoing dynamic story runs, archive/memory, real contract, snapshot progression, annual energy records, world seed, and pending followups.
- `main.js` adds `restoreLifeFileSnapshot(data)`: validate/prepare first, then atomically switch the canonical globals and refresh the dossier; rollback on rendering failure. Do not overwrite Archive/Achievements. Never autosave.
- `js/ui/story-quest-ui.js` adds compact **EXPORT SAVE / IMPORT SAVE** controls (download Blob and selected local JSON only), keyboard labels, visible import/rejection status, and an explicit warning that these files are unencrypted local backups. Keep existing story journal and mobile layout.
- Build `tools/rpg-release-qa.js` (with `--json` and `--write`) for reproducible seeded new-file, load/migrate, active story continuation, 100-year bounded RPG archive/memory and deterministic replay, measuring wall time, snapshot size and Node heap high-water with intentionally generous thresholds based on measured run. Generate `reports/rpg-release-qa.json` and `docs/releases/2026-11-17-rpg-phases-6-12.md` with exact provenance.
- Live Chrome E2E: open a real new game through the UI or programmatically `newFile`, start a real story, download/encode save, start a new life, import/restore old one, complete ongoing story, advance/fast-forward years; test zero-energy and corrupted file not mutating active state; 320/390/768/1440 viewport, keyboard/motion behavior. Physical Android on-device not implied.
- Preserve deterministic RNG, one annual energy ledger, real salary and NPC records. Do not touch protected `js/map.js`, `js/state.js`, `js/systems/world-gameplay.js`, `assets/maps/**`.

## Ship gate
Full existing and new tests, `audit:rpg`, `simulate:rpg`, world/NPC diagnostics, release QA JSON, syntax, Chrome viewports and interactive E2E, `git diff --check`, zero protected map edits. No publishing/deployment without explicit user authorization; note any unverified device coverage as a release limitation.
